# Ponytail & Graphify Rule for Patch 2.0

Enforce Ponytail minimalist engineering principles alongside Graphify architectural clarity across all interactions in this project.

## 🐴 Ponytail Rules (Anti-Overengineering)
- **Decision Ladder**: YAGNI -> Reuse Existing Code -> Standard Library / Native APIs -> Existing Dependencies -> Minimal New Code.
- **Speculative Code Ban**: Do not add unused wrappers, premature abstractions, or unnecessary boilerplate.
- **Simplicity Over Cleverness**: Code must be immediately readable, maintainable, and concise.

## 🕸️ Graphify Rules (Architectural Traceability)
- Maintain clear modular boundaries and distinct entry points.
- Prevent circular dependencies and deeply entangled call graphs.
- Keep blast radius tight so that structural AST/knowledge graph analysis remains clean and debt-free.
